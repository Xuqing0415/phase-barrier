    • 19:34:30：五分钟启动核验通过，26/200 官方评分、13/100 完整配对，源码哈希一致、无新停机原因。原 23 行评分及 266 个原证据文件逐项一致，旧启动快照保留。公开凭据为 benchmarks/swebench/results/scale100-resume1-launch-2026-11-14.json，仅证明该检查点健康。

    根因范围与修复¶

    已确认的问题是状态原子替换没有重试，单次拒绝访问异常导致整个监督器停机。 归档时不存在残留 .tmp；停机后成功写下终态，不能据此反推失败瞬间没有临时文件。 两秒快照和每小时/十配对留档在同一个监督循环执行，没有发现两个并发监督写线程。 外部程序的文件句柄占用是待证实的可能触发因素；没有捕获故障瞬间的句柄持有者，不将杀毒软件、索引或 IDE 写成已证实根因。

    修复在 scripts/verified20_runtime.py 中统一使用线程锁和跨进程文件锁，锁内处理旧 .tmp，写入后 flush/fsync，再执行最多五次原子替换，退避为 0.1/0.2/0.4/0.8 秒。 重试全部失败时保留源临时文件。小时观察器使用同一实现。永久故障停止任务并保留 halt 或备用诊断文件，不自动反复重启。

    测试覆盖瞬时冲突、永久失败、残留临时文件、两个线程各写 100 次、跨进程写入、真实 Windows 无删除共享句柄、停机记录、已评分项禁止覆盖，以及独立进程的两实例崩溃/续跑循环。 模拟产物与正式实验隔离，明确标记 SIMULATION_ONLY，不调用真实模型，不作为正式结果。 进一步将故障注入到实际监督器异常处理路径后，验证了真实工作 PID 登记、停止进程、持久化 halt 和恢复跳过首项；Windows venv 启动器 PID 单独保留，避免误用启动器 PID。 首次在受限沙箱内测试进程终止时被权限限制，测试返回清理失败；仅清理了该模拟目录匹配的两个遗留 Python 进程，在获准的执行环境重跑通过。正式实验没有因此再次启动或停机。

    已有证据的恢复分类¶

    类别 数量 动作
    skip 23 patch、stats、prediction、官方 report、CSV 及 gated trace/state 核验后跳过
    regrade_only 1 django__django-11999 baseline，保留既有补丁与模型耗时，仅补评分
    rerun 1 django__django-12155 baseline，被监督器中断，只有初始工件记录，使用新 attempt
    pending 175 尚未开始，使用新 attempt

    剩余 177 项评分需要 176 次新 Agent 任务及 1 次仅评分。 完成但补丁为空的未知结果不自动重新采样模型；存在不一致的官方证据会阻止恢复，不把缺少 prediction/report 的任务记作 unresolved。

    执行代码与证据隔离¶

    原运行工作区保留冻结的 Agent、规则、样本、协议与 70 个文件。 新监督/恢复代码从单独工作区执行，并显式挂载原执行工作区的 run_agent.py 与 anti_shortcut/。 因此最新主分支上的学习规则元数据刷新不会进入本次实验。 恢复前要求 anti_shortcut/ 相对 v1.2.0 无差异，固定镜像 100/100、容器 DNS、冻结哈希及公开的修复 CI 均通过。 同时逐项比较原始启动与恢复的宿主数据集哈希、脱敏 Agent 数据、镜像/起点证明、模型请求名、strict 和 DNS 参数；私有评分数据及问题描述发生变化会阻止恢复，不能仅凭公开实例 ID 相同放行。

    旧 launch.json、原始 attempt 与归档均保留；活动进程写入 current_launch.json，恢复控制代码单独记录提交与文件哈希。 evidence_index.json 逐任务登记 Agent 与评分标签，最终核验只取选定证据。 运行器保留 strict、60 轮、并发 2、显式 DNS、相同样本与模型请求参数。

    已实现入口如下，路径需按实际工作区填写：

    python scripts/scale100_classify_existing.py --root <运行根> --manifest <原冻结清单> --output <恢复计划>
python scripts/scale100_runtime.py resume --run-root <运行根> --execution-root <原冻结执行工作区> --archive <已验证同级归档> --resume-plan <恢复计划> --attempt-label resume1

    resume 强制检查发布 CI、已提交的模拟验收证明、计划与当前证据一致性。正式重新启动不依赖不存在的旧 --resume-plan 接口。

    成本、收尾与尚未完成事项¶

    django__django-12155 的 Agent 被中断，按外部停机证据排除整个配对的主 P90，保留原始/新 attempt 文件及耗时记录用于敏感性与中断成本审阅。 django__django-11999 baseline 的 Agent 已在故障前完成；仅评分进程被中断不自动排除其 Agent 耗时。 恢复不推断或扣除未知墙钟耗时，不把重新执行耗时说成包含所有失败尝试的总成本。

    统计沿用原预注册：同一组内抽中一对时同时取 baseline/gated，点估计为原样本 P90 比；不独立重采样两组，不用 bootstrap 中位数替换点估计。 不声称 n=100 保证检测某种效应，不把差异不显著写成非劣效。

    本地全量回归通过，核心覆盖率 94%，最终专项 41 项通过；独立故障注入验收通过。正式恢复所用 518d384 的远程主 CI 43589385469 全部 17 个任务成功，包含 Linux Python 3.10–3.14、Windows/macOS 3.12/3.13、覆盖率门槛、打包、性能和集成检查；docs 43589385483、Security 43589385653、Plugin CI 43589385497 同样成功。 首个修复提交 6eac776 的远程回归发现三处 Git 文本子进程查询遗漏显式编码。此前本地全量运行时新恢复脚本尚未进入 Git 跟踪范围，因此仓库的 tracked-file 编码检查未覆盖它；提交后 CI 正确阻止恢复。三处均已补充 UTF-8，并通过静态检查和 518d384 的全量 CI；正式恢复没有沿用失败提交的状态。 机器可读验收位于仓库的 benchmarks/swebench/results/scale100-recovery-validation.json。 后续仍须 200 项/100 对完整证据核验、异常逐项审阅、成本敏感性、最终报告和 v1.2.1 发布。
