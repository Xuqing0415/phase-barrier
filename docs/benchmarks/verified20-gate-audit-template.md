## 归类规则与实例重点

| 类别 | 需要的证据 | 处理 |
|---|---|---|
| A | 同一补丁自写测试通过；官方失败涉及未覆盖或错误断言的行为；无已证实的 B/C 原因 | 披露覆盖边界及混杂，不声称官方集与自写集等价 |
| B | 证实测试修改、删除或降低断言使门禁接受了不充分证据 | 记录实际变更与门禁策略的关系；普通测试修改本身不足以证明篡改；另行修复验证 |
| C | 可复现的交付校验缺陷，例如最终测试不晚于变更仍交付 | 保留最小复现、原状态和源码版本；修复后的运行单列 |
| 待归类 | 环境错误、证据不全或多种原因尚未排除 | 不预填 A，不将未完成重放写成已复现 |

Requests 重点核对 `test_requests.py` 及 `tests/` 的既有测试变更，和网络/证书错误。
Xarray 重点列出官方 FAIL_TO_PASS 完整 ID、警告类型断言与阶段 2/3 的测试变化。
Astropy 重点核对批次：pilot A 类与正式批双组 resolved 的差异分开记录。

汇总仅统计当前正式批实际符合组合的实例；历史案例另列。
门禁通过不是官方 resolved 的充分条件，也不能称为其必要条件。
