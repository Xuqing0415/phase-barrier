# Scale-100 监督器故障与恢复记录

## 已确认的时间线

- 2026-11-14 16:09:09 北京时间：启动固定样本 100 实例、200 任务。
- 17:34:56：监督器替换 `monitor_status.json.tmp` 到 `monitor_status.json` 时出现 `PermissionError / WinError 5`。
- 17:34:59：监督器已停止运行器、清理两个所属容器，持久化停机原因。
- 18:05:10：小时观察器留档终态后正常退出，不代表恢复或继续监控。
- 18:43：将运行根目录完整复制到同级归档，核对 331 个文件、8,772,176 字节，原件及副本哈希一致；额外保存 70 个冻结文件及规则、样本和协议的快照。未删除 `.tmp` 或原始证据。

## 根因范围与修复

已确认的问题是状态原子替换没有重试，单次拒绝访问异常导致整个监督器停机。
归档时不存在残留 `.tmp`；停机后成功写下终态，不能据此反推失败瞬间没有临时文件。
两秒快照和每小时/十配对留档在同一个监督循环执行，没有发现两个并发监督写线程。
外部程序的文件句柄占用是待证实的可能触发因素；没有捕获故障瞬间的句柄持有者，不将杀毒软件、索引或 IDE 写成已证实根因。

修复在 `scripts/verified20_runtime.py` 中统一使用线程锁和跨进程文件锁，锁内处理旧 `.tmp`，写入后 flush/fsync，再执行最多五次原子替换，退避为 0.1/0.2/0.4/0.8 秒。
重试全部失败时保留源临时文件。小时观察器使用同一实现。永久故障停止任务并保留 halt 或备用诊断文件，不自动反复重启。

测试覆盖瞬时冲突、永久失败、残留临时文件、两个线程各写 100 次、跨进程写入、真实 Windows 无删除共享句柄、停机记录、已评分项禁止覆盖，以及独立进程的两实例崩溃/续跑循环。
模拟产物与正式实验隔离，明确标记 `SIMULATION_ONLY`，不调用真实模型，不作为正式结果。
进一步将故障注入到实际监督器异常处理路径后，验证了真实工作 PID 登记、停止进程、持久化 halt 和恢复跳过首项；Windows venv 启动器 PID 单独保留，避免误用启动器 PID。
首次在受限沙箱内测试进程终止时被权限限制，测试返回清理失败；仅清理了该模拟目录匹配的两个遗留 Python 进程，在获准的执行环境重跑通过。正式实验没有因此再次启动或停机。

## 执行代码与证据隔离

原运行工作区保留冻结的 Agent、规则、样本、协议与 70 个文件。
新监督/恢复代码从单独工作区执行，并显式挂载原执行工作区的 `run_agent.py` 与 `anti_shortcut/`。
因此最新主分支上的学习规则元数据刷新不会进入本次实验。
恢复前要求 `anti_shortcut/` 相对 v1.2.0 无差异，固定镜像 100/100、容器 DNS、冻结哈希及公开的修复 CI 均通过。

旧 `launch.json`、原始 attempt 与归档均保留；活动进程写入 `current_launch.json`，恢复控制代码单独记录提交与文件哈希。
`evidence_index.json` 逐任务登记 Agent 与评分标签，最终核验只取选定证据。
运行器保留 strict、60 轮、并发 2、显式 DNS、相同样本与模型请求参数。

已实现入口如下，路径需按实际工作区填写：

```powershell
python scripts/scale100_classify_existing.py --root <运行根> --manifest <原冻结清单> --output <恢复计划>
python scripts/scale100_runtime.py resume --run-root <运行根> --execution-root <原冻结执行工作区> --archive <已验证同级归档> --resume-plan <恢复计划> --attempt-label resume1
```

`resume` 强制检查发布 CI、已提交的模拟验收证明、计划与当前证据一致性。正式重新启动不依赖不存在的旧 `--resume-plan` 接口。
